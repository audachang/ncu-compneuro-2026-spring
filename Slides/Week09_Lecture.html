§1.12 關鍵洞察 — 為什麼「非資工背景」受益最大?

原因 01

起點門檻

資工背景本就第一版快寫完,AI 提升不顯著。非資工者的第一版常需 1–2 天,AI 能壓到 1–2 小時。

原因 02

語言優勢

研究者的強項是「精確描述現象」。Vibe coding 需要的正是這個 — 把意圖講清楚,不是把語法寫對。

原因 03

領域知識

AI 懂語法但不懂你的領域。認知神經、語言學、社會學的 domain expertise 反而是無可替代的 edge。

§1.13 新的核心技能:Express + Verify

Human Idea 🧠
Verified Code ✓

Express · 精確表達

把模糊想法變成明確規格。用「結果語言」而非「步驟語言」描述,主動講清邊界條件、例外、驗收標準。

核心訓練 → 寫 spec / prompt / CLAUDE.md

Verify · 嚴謹驗證

讀 AI 的程式並理解關鍵幾行,跑測試、對比樣本、檢查邊界值。辨識幻覺訊號(例如不存在的 API)。

留下可重現的紀錄 → 程式本身就是紀錄

§2.10 該用哪一層? — 四象限決策

QUAD A · 低複雜度

便宜、即時、風險低。

→ L1 Copilot 或 L2 Chat
QUAD B · 中複雜度

加新欄位 / 小重構

在 diff 層級做最安全。

→ L3 IDE
QUAD C · 高複雜度 ⭐

本課主打:資料清理、分析 workflow。

→ L4 Agentic CLI
QUAD D · 跨天、跨系統

→ L4 + 人類審查

SECTION 03

Vibe Coding 的三個工作原則

一組可操作的守則 — 讓 AI 成為合作者,而不是亂源。

PRINCIPLE 01

Describe, Don't Dictate

用「結果」描述,不用「步驟」命令。精確性 > 禮貌。

PRINCIPLE 02

Plan-Execute-Verify

先 AI 提計畫,你核可再執行,最後驗證。三階段不可省。

PRINCIPLE 03

Small Commits, Short Context

小步走、常 commit,讓 context 永遠乾淨。風險 isolate。

§3.3–3.4 Prompt 對照:同一需求,兩種寫法

❌ Dictate 幫我寫 Python, 先 import pandas, 然後 read_csv, 然後 groupby subject, 然後 mean RT, 然後畫圖, 然後存成 png,謝謝 # 沒講資料欄位 # 沒講為什麼分組 # 沒講圖的樣式與存檔位置 # → AI 會瞎猜
✓ Describe 資料:data/tidy/rt.csv 欄位:subject_id, condition (congruent/incongruent), rt_ms, trial 任務: 1. 依 subject × condition 算 mean/sd 2. seaborn bar + errorbar(sd) 3. figures/rt_by_cond.png (300 dpi) 限制: - 使用 pathlib - RT < 100ms 視為 outlier,先 drop - 若有 NaN,raise ValueError

§3.5 好 Prompt 的六個欄位

01

Input · 資料在哪

路徑 + column 名 + dtype + 約略列數

02

Output · 期待格式

DataFrame? 圖? 檔案? 要什麼欄位?

03

Constraint · 限制

套件版本、效能、禁止的手法

04

Edge case · 邊界

NaN、outlier、重複、空檔怎麼處理

05

Success · 驗收

row 數、值的範圍、特定輸出

06

Style · 風格

snake_case、type hint、註解深度

§3.6 Plan → Execute → Verify 三段流程

📝

Plan

AI 先列「打算分幾步、touch 哪些檔、風險點、產物」。
你核可再放行。

→
⚡

Execute

AI 一次跑完一個 atomic unit。
中途不插嘴改需求 — 會讓 context 很髒。

→
✅

Verify

實際執行 · 輸出值對期望 · 抽樣讀關鍵幾行 · 幻覺檢查。

為什麼重要:省下『錯 50 步才發現第 2 步錯』的浩劫。PEV 也是研究方法 — hypothesis → experiment → check,同一個思維。

§3.11 原則 3:Small Commits, Short Context

#c6d8e3
plot: bar + errorbar
#d7f9a4

#e8a0b5

現在位置 ✓

每次 AI 改動控制在「幾十行、單一目的」。任何時刻可 git checkout 回到對的狀態。

無 AI 時代

  • 慢,錯也慢;每次改動量小
  • 人腦能守住 working memory
  • 錯了多半是邏輯,rollback 選擇性多

AI 時代 — 風險新形態

  • 一個 prompt 可能改 20 個檔
  • 幻覺是『像真的錯』,肉眼難察
  • 累積 5 個 prompt 才 commit,debug 等於重啟研究
→ 小 commit 是最便宜的保險

§3.13 Git 速查 — 研究者版

# 觀察
git status                           # 現在有哪些改動?
git diff                             # 差在哪幾行?
git log --oneline -10                # 最近 10 個 commit

# 分 commit 的關鍵
git add -p                           # 選擇性加入
git commit -m "clean: drop RT<100"

# Rollback
git checkout <sha> -- path/file.py    # 把某個檔退回
git reset --hard HEAD~1              # 整個 commit 丟棄(小心)

§4.5 可重現 — 你與 AI 的共同責任

01

紀錄 prompt

關鍵 prompt 存進 repo(例如 prompts/clean_rt.md)。

02

鎖套件版本

requirements.txt / environment.yml,含 Anthropic SDK 版本。

03

留 seed

隨機性操作使用固定 seed,且寫進 CLAUDE.md。

04

方法章節揭露

使用了哪個模型、哪個版本、做什麼子任務。

⚠️ LLM 同樣 prompt 不保證同樣輸出 → 程式是主產物,prompt 是脈絡。

§4.10 絕對不要貼進雲端 LLM 的資料

🚫 受試者個資

  • 姓名、學號、email、電話、身分證
  • 未發表的影像 / 生理訊號 / 問卷原始資料
  • 依 IRB 條款尚未核准公開者

🚫 未公開研究資料

  • 合作單位資料(醫院病歷、公司營運)
  • 合作研究者未同意公開的 manuscript
  • API key、password、server credentials

§4.11 學術誠信 — 怎麼用與怎麼說

❌ 不合誠信

  • 繳交整段 AI 生成程式,不 review 不驗收
  • 論文內容整段 AI 寫,未揭露
  • 讓 AI 幫你編造資料或引用
  • 複製他人含 AI 的作業,掩蓋來源

✓ 合誠信

  • AI 起手 + 自己驗證 + 揭露
  • 把 prompt 與 diff 留檔,方便審閱
  • 引用 AI 產生片段,如同引用 collaborator
  • 在 acknowledgement / methods 清楚寫

§4.14 何時不要使用 AI

情境 01

你在學

第一次學 pandas / numpy,要親手寫幾次。AI 會讓你以為自己懂。

情境 02

受試者敏感資料

即便去識別化也要三思。首選本機模型或完全不用。

情境 03

核心論證

論文核心結果、關鍵統計 — 親手跑過、理解每一行。

「AI 是腳手架,不是建築師。自問一句:如果明天 AI 都斷線,我還能繼續做研究嗎?」 — §4.15 最重要的一條:不外包思考
